## 1. Executive Project Summary

**DeskTrack** is an enterprise-grade workstation presence and activity monitoring platform designed for 50+ concurrent employees. It provides:

1. **Browser-Based Face Verification & Live Monitoring:** Continuous YuNet AI face detection and verification through the employee's browser webcam.
2. **Background Desktop Agent:** A lightweight Python background service on employee workstations tracking active windows, browser tab titles, and lock/sleep states.
3. **1-Click Self-Contained Installer:** Employees download a single `.bat` file from their portal that automatically unpacks Python and the tracking agent with zero configuration.
4. **HR & Lead Analytics Dashboard:** Live office attendance board, historical date-based reports, tracked application breakdowns with interactive modals, and CSV export.
5. **WhatsApp Movement Approvals (WAHA):** Real-time interactive poll buttons (`[ ✅ Approve ]` and `[ ❌ Decline ]`) sent simultaneously to multiple HR phones whenever an employee requests to step away on official tasks.

## 2. Complete Project Evolution & Chronological History

Below is the complete chronological log of all iterations, problems encountered, and architectural decisions resolved from the beginning to the current production state:

### Phase 1: Core Metric Partitioning (Decision 1 & 3)
- **Problem:** Idle time was initially calculated against a fixed 9-hour workday. If an employee clocked in for only 1 hour, they were incorrectly charged 8 hours of idle time. Furthermore, taking a 15-minute break did not properly deduct from their break allowance when the screen slept.
- **Solution:** Strictly bounded all metrics (`seated`, `idle`, `break`, `presence %`) between the employee's actual Clock In and Clock Out timestamps. Total clocked shift $T_{\text{clocked}} = \text{elapsed}$. Break deductions were tied directly to cumulative absence from the desk.

### Phase 2: 1-Click Workstation Auto-Connector (Decision 2)
- **Problem:** Installing desktop trackers manually across 50+ employee PCs required manual token configuration, Git clones, and Python setup. Early `.bat` scripts used fragile HTTP downloads from the server which often 404'd or failed due to network proxies.
- **Solution:** Replaced external downloads with an embedded base64 payload. The `.bat` script generated by `main.py` embeds the entire `desktrack_agent.py` code directly inside itself using a `findstr` payload marker. It auto-detects Python (or quietly downloads official Python 3.11 if missing), installs `requests` and `pywin32`, and registers a Windows Startup task.

### Phase 3: Away-on-Task & Room Movement Approval (Decision 4 & 5)
- **Problem:** When employees left their desk for valid work (conference room meetings, client calls, lab tasks), the webcam marked them as "Away", which burned their personal break budget or penalized them as Idle.
- **Solution:** Added a `TaskRequest` system (`models.py`) with a **"Step Away on Task"** button on the desk page. Employees pick a reason (Meeting, Client call, Other room) and expected minutes. Once approved, the time spent away is credited to **Productive Work**, never penalizes Idle, and does not burn personal break allowance. Added runtime SQLite table self-healing (`Base.metadata.create_all()`).

### Phase 4: WhatsApp Integration via WAHA & Single-Action Buttons (Decision 6, 7 & 8)
- **Problem:** Leads were not always sitting at their DeskTrack dashboard to approve tasks. Initial attempts to send WhatsApp messages with HTTP approval links caused **WhatsApp server link-preview crawlers to fetch the links and prematurely approve tasks before the Lead saw them**. Additionally, Meta deprecated older MD buttons.
- **Solution:**
  - Integrated **WAHA (WhatsApp HTTP API)** running in a companion Docker container on the VPS.
  - Switched from HTTP links to **native WhatsApp Interactive Buttons via Polls** (`/api/sendPoll`).
  - Completely **eliminated links from WhatsApp messages** to prevent crawler auto-clicks.
  - When the Lead taps `[ ✅ Approve ]` or `[ ❌ Decline ]`, WAHA delivers a `poll.vote` webhook to `/api/webhooks/waha`, resolving the request in real time.
  - Webhook also accepts natural single-word replies (`approve`, `approved`, `ok`, `yes`, `reject`, `no`).

### Phase 5: Concurrency & Time-Partitioning Integrity (Decision 9 & 10)
- **Problem:** 
  1. Testing tasks while seated at the desk double-credited both seated and task time, which erased previous morning idle and inflated presence to 92%.
  2. Leaving the screen active while away caused background apps to accumulate into `Active (apps)` beyond the total clocked shift time.
  3. Face enrollment required 5 samples, leading to employee confusion.
  4. 50+ concurrent employees writing heartbeats risked SQLite database locks.
- **Solution:**
  - **Strict Time Partitioning:** At any second during a clocked shift:
    $$T_{\text{clocked}} = T_{\text{seated}} + T_{\text{task\_away}} + T_{\text{break\_used}} + T_{\text{idle}}$$
  - **Active Apps Bounded:** App accumulation is strictly suppressed when `present == 0` or locked.
  - **2-Sample Face Enrollment:** Lowered enrollment requirement to 2 clean snapshots.
  - **SQLite WAL & Timeout:** Activated `PRAGMA journal_mode=WAL;` and `PRAGMA busy_timeout=10000;`. Concurrent writes never block reads.
  - **Polling Optimization:** Shifted `/api/me` poll from 3s to 10s since `/api/me/track` already streams metrics, slashing server HTTP traffic by 60%.

### Phase 6: Tab Switching Flash & Instant Camera Startup (Decision 11)
- **Problem:** Switching tabs between "Account" and "My desk" caused a 400ms flash where the UI rendered "Clocked Out" and displayed a large "Face enrollment required" card before the API returned.
- **Solution:** Cached active state in `sessionStorage` (`desktrack_me` and `desktrack_face`). Added a `loaded` guard so enrollment prompts only render after server confirmation, and initiated the camera immediately on mount if cached as clocked in.

### Phase 7: Docker Build Fix for 1-Click Installer (Decision 12)
- **Problem:** Saniya (and other employees) saw `Failed to obtain tracker from server` when running the `.bat` file. The server container lacked the `agent/` directory because `Dockerfile` did not copy it, making `$agentB64` empty. Subsequent Docker builds on the VPS failed because `.dockerignore` excluded `templates/` and `static/`.
- **Solution:** Cleaned `Dockerfile` to strictly copy `agent/` and the built `frontend/dist/`. The `.bat` installer is now 100% self-contained.

### Phase 8: Historical Date-Based Tracked Apps & Popup Modal (Decision 13 & 14)
- **Problem:** HR could only see apps used "today". Historical days lacked app data, and clicking an employee from the Daily Report reset the date. The `+N more` app tag was static text.
- **Solution:**
  - Added date picker (`day`) with "Today" quick button to `Employee.jsx`.
  - Added "Tracked apps" column to `/hr/reports` with compact badges.
  - Preserved `?day=YYYY-MM-DD` query param across employee links and CSV exports.
  - Converted `+N more` into an interactive button that launches a **Tracked Applications Pop-up Modal** displaying all apps, duration bars, and total active time.

### Phase 9: Multi-HR WhatsApp Approvals & Policy Adjustments (Decision 15)
- **Problem:** Company policy required:
  1. Multiple HR phone numbers to receive movement approval requests simultaneously.
  2. Increasing the face absence buffer to 15 minutes before marking as Away.
  3. Increasing the daily break allowance from 30 minutes to 1 hour (60 minutes).
  4. If an employee is away beyond the 15-minute buffer, reduce their 1-hour break time. Only when the 1-hour break is completely used up should additional unapproved away time go into Idle.
- **Solution:**
  - Implemented `get_lead_phone_numbers()` in `waha.py` to parse comma/space-separated numbers from `LEAD_WHATSAPP_PHONE`. Broadcasts approval polls to all HR numbers.
  - Increased `IDENTITY_HOLD_SECONDS = 900` (15 mins) and `PRESENCE_GAP_GRACE_SECONDS = 900`.
  - Increased `BREAK_ALLOWANCE_SECONDS = 3600` (1 hour).
  - Updated `analytics.py` partitioning:
    - $\text{Unapproved Away} = \max(0, T_{\text{non-seated}} - T_{\text{task\_away}})$
    - $\text{Break Used} = \min(\text{Unapproved Away}, 3600)$
    - $\text{Break Left} = \max(0, 3600 - \text{Unapproved Away})$
    - $\text{Idle Time} = \max(0, \text{Unapproved Away} - 3600)$

### Phase 10: Automatic Weekly WhatsApp Report (Decision 16)
- **Problem:** Management and HR needed an automated weekly overview for every employee sent automatically every Sunday without requiring HR to manually pull reports. The report needed to summarize screen time, seated vs. idle times, and main applications used.
- **Solution:**
  - Added `weekly_report.py` to aggregate 7-day attendance and application tracking metrics across all active employees.
  - Formatted WhatsApp message with screen time, days active, seated, idle/away, active apps, presence % with ASCII progress bar, and top 3 apps used with exact durations.
  - Background scheduler thread wakes up every minute and automatically dispatches to all numbers in `LEAD_WHATSAPP_PHONE` every Sunday at 09:00 AM IST (configurable via `WEEKLY_REPORT_DAY`, `WEEKLY_REPORT_HOUR`, `WEEKLY_REPORT_MINUTE`).
  - Added HR API endpoints `GET /api/hr/weekly-report/preview` and `POST /api/hr/weekly-report/send`.
  - Added `📱 Weekly Report` interactive modal to the HR Daily Report page (`Reports.jsx`) with live preview, copy-to-clipboard, and manual dispatch button.

## 3. Core Business Rules Cheat Sheet

| Parameter / Rule | Value | Explanation |
| :--- | :--- | :--- |
| **Face Absence Buffer** | **15 minutes** (`900s`) | If face leaves camera frame, employee remains marked **Present/Seated**. Not added to idle or break. |
| **Daily Break Budget** | **1 hour** (`3600s`) | Daily personal break allowance. |
| **Away State** | $> 15$ mins absence | After 15m without face, employee transitions to Away. |
| **Break vs. Idle Rule** | Break-first deduction | Away time consumes the 1h break budget. Once the 1h budget is exhausted, excess time accumulates into **Idle time**. |
| **Approved Tasks** | 100% Productive | Movement approved by HR is credited as work; does not consume break or add to idle. |
| **Shift Completion** | Single daily shift | Once an employee clocks out, they cannot re-clock in on the same calendar day. |
| **Multi-HR WhatsApp** | Comma-separated | `LEAD_WHATSAPP_PHONE=919167..., 919930...`. All numbers receive the poll; any one can approve. |

## 6. How to Run, Test & Deploy

```bash

ssh root@<vps-ip>

# 2. Navigate to project folder
cd /opt/desktrack

# 3. Pull latest changes from GitHub
git pull origin main

# 4. Rebuild and restart container
```

## 7. Crucial Tips & Nuances for the Next Developer

1. **Always edit within Git:** The production VPS tracks `origin/main`. Always commit and push from the workspace so the server can run a clean `git pull origin main`.
2. **Docker Ignore Caution:** Never add `agent/` to `.dockerignore`. The Docker build must copy `agent/` into `/app/agent/` so the server can embed the tracker into `.bat` downloads.
3. **WAHA Interactive Poll Webhook:** WAHA sends poll votes as `event: "poll.vote"` or with `vote` in payload. The backend auto-resolves the latest pending request when a button is clicked.
4. **Camera HTTPS Requirement:** Browsers strictly block webcam access on insecure HTTP (except `localhost`). Production must always be accessed via `https://`.
5. **SQLite WAL Concurrency:** Database file is stored at `/app/data/office.db` on the VPS volume. WAL mode ensures that live heartbeats from 50+ users do not cause database lock timeouts.
